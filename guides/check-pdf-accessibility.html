How to check if a PDF is accessible

Five quick checks, then the tools that go deeper, and what none of them can tell you.

Five quick checks

  1. Can you select the text? If you can't highlight a sentence, the page is a picture of text (a scan). Screen readers get nothing until it is run through OCR.
  2. Is it tagged? In Adobe Acrobat, open File › Properties: "Tagged PDF: Yes" means there is a structure tree. "No" means a screen reader has to guess everything.
  3. Is the language set? Same dialog, Advanced › Language. Without it, screen readers may read English with the wrong voice and pronunciation.
  4. Does it have a real title? The title bar should show a title, not a file name like scan0042.pdf.
  5. Do the images have alt text? Hover an image with the Acrobat Tags panel open, or use a checker that reads the structure tree.

Deeper tools

  • veraPDF: the open-source validator for PDF/UA-1 (ISO 14289-1). It tests every rule a machine can test.
  • PAC (PDF Accessibility Checker): a free Windows tool that runs the machine-checkable Matterhorn Protocol tests and shows a screen-reader preview.
  • Acrobat Pro's Accessibility Checker: useful, but it passes some files that fail PDF/UA, and it can't judge quality.
  • A screen reader: NVDA (free, Windows) or VoiceOver (built into macOS and iOS). Ten minutes listening to your document tells you more than any score.

What machines can't check

The Matterhorn Protocol lists 136 failure conditions for PDF/UA. 87 can be tested by software; the rest need judgement. Software can tell you an image has alt text, not whether "image1.png" or "chart" describes it. It can tell you headings exist, not whether the reading order makes sense.
